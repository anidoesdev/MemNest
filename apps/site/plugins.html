Install

Give your assistant a memory

Memnest connects over MCP, the protocol assistants use to reach outside tools. Pick your client below. Memories are stored on your own machine, and you can read, correct or delete them at any time.

A container tag, kind:id. Everything below updates to match. Use one tag for one person or project; clients sharing a tag share one memory.

Claude Code

Plugin, with slash commands

The plugin adds the memory tools plus /memnest:memories, /memnest:remember and /memnest:forget. Run these in Claude Code:

/plugin marketplace add anidoesdev/MemNest
/plugin install memnest@memnest

or just the server:

claude mcp add memnest -- npx -y @memnest/cli mcp --container user:me

Share one memory
Across clients and people

          
Run a server, create a key scoped to a container, then point every client at it with --url instead of a local database. Everyone sees the same memories, and the dashboard shows what is stored.

          
memnest keys create --name claude --container user:me
npx -y @memnest/cli mcp --url https://memnest.example.com   # with MEMNEST_KEY set

        

      


      

        
After installing

        

          
1 · Teach it something"Remember that I deploy only after 2pm on Fridays." It calls remember and stores one atomic fact.

          
2 · Open a new chatAsk "when can I deploy?". It calls recall and answers from memory, not from this conversation.

          
3 · Change your mind"Actually we deploy any time now." The old fact becomes history instead of a second, competing truth.

        

        
Nothing is sent anywhere: memories live in ~/.memnest/memnest.db on your machine. See Managing your memories to read, correct or erase them, and Chat clients for read-only mode and shared setups.

      


      

        
Questions

        
Do I need a model or a database?
No. remember and recall work immediately with SQLite and keyword search. Add a completion model to have Memnest extract facts from whole conversations by itself, and Postgres + pgvector for semantic search.

        
Can the assistant read another person's memories?
No. The container is fixed by your configuration or the API key, and no tool takes one as an argument, so text the model reads cannot redirect it. See Security.

        
Can I stop it writing to memory?
Add --read-only to the arguments. The assistant can still recall, view history and read the profile, but cannot store, change or forget anything.

        
Where do I see everything it has stored?
memnest memories list --all --container user:me --db ~/.memnest/memnest.db, or run the dashboard against the same database for the graph, lineage and traces.

        
The command needs npm. Is that required?
npx comes with Node.js, which most of these clients already need. If you would rather not use it, install the CLI globally (npm i -g @memnest/cli) and use memnest as the command, or point the client at a Node binary and the CLI's path.
