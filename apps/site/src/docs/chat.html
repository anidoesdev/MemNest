Memnest speaks MCP, the protocol assistants use to reach outside tools. Connect it once and your assistant can recall what you told it weeks ago, record new facts, and correct what it got wrong — in any conversation, not just the one where you said it.

Install for your client →

Set it up

As a plugin, which adds /memnest:memories, /memnest:remember and /memnest:forget alongside the tools:

/plugin marketplace add anidoesdev/MemNest
/plugin install memnest@memnest

Or the server on its own:

claude mcp add memnest -- npx -y @memnest/cli mcp --container user:me

In claude_desktop_config.json (Settings → Developer → Edit Config), then quit Claude from the tray and reopen it:

{
  "mcpServers": {
    "memnest": {
      "command": "npx",
      "args": ["-y", "@memnest/cli", "mcp", "--container", "user:me"]
    }
  }
}

On Windows, if the server does not appear, give the full path to Node instead of npx: "command": "C:\\Program Files\\nodejs\\node.exe" with the CLI's path as the first argument. Claude Desktop does not always inherit your PATH.

In .cursor/mcp.json for one project, or ~/.cursor/mcp.json for all of them:

{
  "mcpServers": {
    "memnest": {
      "command": "npx",
      "args": ["-y", "@memnest/cli", "mcp", "--container", "user:me"]
    }
  }
}

What your assistant can do

ToolWhat it does
recallSearches for current facts about a question, inside a token budget. Says how many older facts it left out, and why.
rememberStores facts, one sentence each. Exact duplicates are skipped. To record a change it passes the outdated memory's id as supersedes, so the old one becomes history rather than a rival truth.
ingestHands over raw notes or a transcript for Memnest to extract facts from itself. Needs a completion model.
forgetStops serving a memory that is wrong. It stays in history.
historyWhere a memory came from and how it changed.
profileA short summary of everything durable. Also offered as the resource memnest://profile.

The server also sends instructions telling the assistant when to recall and how to record a change, so this mostly happens without you asking.

Try it

  1. Teach it something. "Remember that I deploy on Fridays only after 2pm, and that our staging database is Postgres 16."
  2. Start a new conversation and ask: "When can I deploy?" It should call recall and answer from memory.
  3. Change a fact. "We moved staging to MySQL." Ask what staging runs on: you get MySQL, and the Postgres fact is kept as history rather than deleted.
  4. Correct a mistake. "That's wrong, forget it." See Managing your memories.

Where your memories live

By default in ~/.memnest/memnest.db on your own machine, created on first use. Nothing is sent anywhere. Point several clients at the same container to share one memory between them, or give each its own:

SettingEnvironmentWhat it does
--container <tag>MEMNEST_CONTAINERWhose memory this is. Required.
--db <path>MEMNEST_DBWhere the SQLite file lives.
--database-url <url>MEMNEST_DATABASE_URLUse Postgres + pgvector instead, for semantic recall.
--url <url>MEMNEST_SERVER_URLUse a Memnest server, with MEMNEST_KEY. The key's scope sets the container.
--read-onlyMEMNEST_MCP_READ_ONLYOnly recall, history and profile: the assistant can read memory but not change it.

Share one memory across clients and people

Run a server, create a key scoped to a container, and point every client at it. Then Claude Desktop, Cursor and your own app all see the same memories, and a person can review them in the dashboard.

memnest keys create --name claude --container user:me   # printed once
{
  "mcpServers": {
    "memnest": {
      "command": "npx",
      "args": ["-y", "@memnest/cli", "mcp", "--url", "https://memnest.example.com"],
      "env": { "MEMNEST_KEY": "mnk_…" }
    }
  }
}

What the assistant cannot do

  • Reach another container. The container comes from your configuration or the API key, never from a tool argument, so text the model reads cannot redirect it at someone else's memory.
  • Store a secret. Credentials are redacted before anything is written, and a candidate carrying one is rejected.
  • Quietly rewrite the past. Nothing is edited in place. A change writes a new version and keeps the old one; a deletion is recorded.
