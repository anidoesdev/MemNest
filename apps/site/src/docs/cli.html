npm install -g @memnest/cli
memnest --help

SQLite by default (--db, or MEMNEST_DB, default ./memnest.db), Postgres with --database-url or MEMNEST_DATABASE_URL. Add --json to any command for machine-readable output.

Commands

CommandWhat it does
migrateApply pending schema migrations
ingest <file…> --container <tag>Add documents (.json turns, .md, .txt); --custom-id, --extraction, --date
search <query> --container <tag>Recall with the trace; --budget, --candidates
memories list --container <tag>List memories; --all includes superseded and forgotten, --kind, --limit
memories add <content>Write directly; --kind, --confidence, --supersedes, --extends, --valid-until
forget <memoryId>Soft-delete a memory
lineage <memoryId>Show what it replaced, what extends it, and its sources
jobs · jobs run · jobs retry <id>List (--status), process what is due, or requeue a failed job
workerProcess extraction jobs until stopped
runs --container <tag>Extraction runs with decisions and rejections; --document
profile --container <tag>The cached profile; --rebuild to build now
backfill --container <tag>Embed memories and chunks that have no vectors yet
seed --container <tag> --count <n>Synthetic memories with real structure, to explore the dashboard
providers check · providers envCall the configured endpoints · list every variable
serveHTTP server (REST + SSE) and, with a model, the worker; --port, --host, --dashboard
mcp --container <tag>MCP server over stdio for chat clients; --url, --read-only
keys create --name <name>Create an API key (--container to scope); shown once
keys list · keys revoke <keyId>List or revoke keys (revoking also ends sessions)
evalRun the eval suite; --live, --store, --case

Recipes

# Ingest a conversation and extract it now, rather than waiting for the session to go quiet
memnest ingest chat.json --container user:123 --custom-id chat-42 --extraction instant
memnest jobs run

# What does it believe, and why did it answer that?
memnest profile --container user:123
memnest search "which database?" --container user:123 --budget 200

# Fix a wrong fact, keeping the history
memnest memories add "The user moved to Berlin." --supersedes mem_0042 --container user:123

# Explore the dashboard with 10,000 synthetic memories
memnest seed --container demo:big --count 10000 && memnest serve --dashboard apps/dashboard/dist

Scripting

memnest search "database" --container user:123 --json | jq '.memories[].memory.content'
memnest memories list --container user:123 --json | jq -r '.[] | select(.isLatest) | .id'
