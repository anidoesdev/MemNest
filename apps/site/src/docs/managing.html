Memory is only trustworthy if you can look at it and fix it. Everything here works from your chat, from the command line, and from the dashboard.

See what is remembered

With the Claude Code plugin, /memnest:memories lists what is stored, with each memory's id. In any MCP client, asking "what do you remember about me?" calls profile, and "what do you know about my database setup?" calls recall.

memnest memories list --container user:me              # current memories
memnest memories list --all --container user:me       # including superseded and forgotten
memnest profile --container user:me
memnest lineage <id> --container user:me              # where one came from
memnest runs --container user:me                      # what was extracted, and what was rejected

Add --db ~/.memnest/memnest.db if you are looking at the database your chat client uses.

The dashboard shows the memory graph, one memory's lineage, the retrieval trace for any query, and a topic's history over time. Forgetting is two clicks, with confirmation.

Correct something

Which action you want depends on what happened to the fact:

SituationDo thisResult
It was true, now it isn't ("I moved to Berlin")Store the new fact with supersedes set to the old one's idThe new version is served; the old is kept, linked, and dated
It was never true (the assistant misread you)forget itOut of search and profiles at once, kept for audit
It's true but incompleteStore the extra detail with extendsBoth stay current, linked
A whole conversation shouldn't have been storedDelete the documentIts text and chunks are erased; memories keep a traceable source
Erase everything for this person or customerDelete the containerHard delete of documents, chunks, memories and vectors
 
memnest forget <id> --container user:me
memnest memories add "The user lives in Berlin." --supersedes <old-id> --container user:me

Memories are never edited in place. Every correction is itself a recorded event, which is what makes the history worth trusting.

Erase everything

One call removes a container and everything in it. It is the path for a deletion request.

await memnest.deleteContainer(scopeOf('user:me'));
// or over HTTP:
curl -X DELETE localhost:8787/v1/containers/user:me -H "Authorization: Bearer $MEMNEST_KEY"

SQLite runs with secure_delete, so erased content leaves no residue in the file. A test greps the raw database, its write-ahead log and shared memory to prove it.

Let facts expire

A fact that is only true for a while can carry validUntil. It stops being served the moment it passes, and the trace reports it as expired rather than silently dropping it. Extraction sets this itself for things like "the review is on 24 June at 15:00".
